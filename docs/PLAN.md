# План проекта «Поле»

> Рабочее название игры — **Поле**. Это мобильная idle/clicker-игра в средневековом
> сеттинге, вдохновлённая Magic Research. Документ — единственный источник правды
> о замысле. Любая сессия с агентом начинается с чтения этого файла.

## 1. Суть игры

Игрок начинает с пустого поля и 100 единиц энергии. Кликами добывает дерево, камень
и железо, строит дом, склад и ратушу, нанимает работяг и постепенно превращает
поле в средневековое хозяйство. Цель — проходить эпохи, открывать постройки,
исследования и механики.

Референс: **Magic Research** (мобильная idle-игра). Берём ощущение: клики, ресурсы,
постройки, работяги, постепенное открытие систем.

## 3. Главный экран — спека

### 3.1. Верхняя панель (статичная)

```
[☰]                    Поле                    [🔔]
```

- Слева — бургер-меню. Позже: рынок, что выгодно производить и продавать.
- По центру — название текущей локации/эпохи. Сейчас «Поле», позже меняется
  на «Кузница», «Мануфактура» и т.д.
- Справа — колокольчик уведомлений.

### 3.2. Прокручиваемая часть

Порядок разделов строго сверху вниз. Каждый раздел сворачивается/разворачивается
стрелкой справа от заголовка.

1. **Отдых**
   - Кнопка «Отдых».
   - У кнопки своя стрелка: разворачивает информацию, сколько даёт за клик
     (например, «+1 энергия за клик»).
2. **Сбор**
   - Кнопки: «Собрать камень», «Собрать дерево», «Собрать железо».
   - У каждой кнопки стрелка с информацией о доходе за клик.
3. **Продукция**
   - Кнопки: «Лесопилка», «Угольная яма», «Кузница».
   - Позже в новых эпохах появятся новые кнопки.
4. **Хранение**
   - «Склад», «Амбар» (позже/по прогрессу), «Банк» (увеличивает лимит золота).
   - Список может расширяться.
5. **Дома**
   - «Дом для работяг».
   - «Исследовательская лаборатория» (исследования зданий/чертежей/предметов).

### 3.3. Статичная нижняя часть

## 4. Игровые системы

### 4.1. Энергия

- Старт: 100 / 100, регенерация 1/с.
- Клик по лесу/камню/железу тратит 1 энергию.
- «Отдых» восстанавливает энергию (детали позже).
- Дом повышает регенерацию (например, +1/с за уровень).
- Энергия не может превысить максимум.

### 4.2. Ресурсы и лимиты

| Ресурс | Источник | Лимит |
|---|---|---|
| Дерево | клик по лесу, лесоруб | склад |
| Камень | клик по камню, каменотёс | склад |
| Железо | клик по железу, шахтёр | склад |
| Уголь | угольная яма | склад |
| Золото | продажа/налоги (уточняется) | банк |

- Без склада ресурсы упираются в базовый потолок и не капают дальше.
- Склад повышает лимит дерева/камня/железа/угля.
- Банк повышает лимит золота.

### 4.3. Постройки (строго по порядку открытия)

1. **Свой дом** — первая постройка. Повышает регенерацию энергии.
2. **Склад** — повышает лимит ресурсов.
3. **Ратуша** — открывает остальные постройки.
4. После ратуши:
   - **Дом для работяг** — даёт 1 работника за уровень.
   - **Угольная яма** — переработка дерева в уголь.
   - **Кузница** — переработка руды в железо и создание мечей.
   - **Контора управляющего** — позволяет нанять менеджера для автоплатежей.

### 4.4. Работяги

- Дом для работяг даёт работников.
- Профессии: дровосек, шахтёр, каменотёс.
- Доход в секунду:
  - Лесоруб: 1 дерево/с.
  - Каменотёс: 0.5 камня/с.
  - Шахтёр: 0.1 железа/с.
- Улучшение профессии: за 100 золота доход конкретного работяги ×2.
- Оплата труда (позже): раз в минуту списывается золото; если не заплатил —
  работяга уходит в запой и не работает, пока не заплатишь.

### 4.5. Открытые вопросы

- **Откуда берётся золото?** Варианты: продажа ресурсов на рынке, налоги ратуши,
  продажа мечей. Нужно решение до v0.5.
- **Шахтёр даёт руду или железо?** В концепте и то, и другое. Предложение:
  шахтёр даёт руду, кузница плавит руду в железо. Либо упростить: шахтёр даёт
  железо, кузница куёт мечи.
- **Оффлайн-прогресс:** начислять доход за время отсутствия? Обычно да, с потолком.
- **Название игры:** «Поле» — рабочее.

## 5. Архитектура кода

```
medieval-idle/
├── AGENTS.md              # правила для агентов
├── Cargo.toml
├── Dioxus.toml
├── docs/
│   └── PLAN.md            # этот файл
├── assets/
│   └── main.css
└── src/
    ├── main.rs            # точка входа, launch(App)
    ├── game/
    │   ├── mod.rs
    │   ├── state.rs       # GameState, ресурсы, постройки
    │   ├── balance.rs     # числа, стоимости, формулы
    │   └── actions.rs     # чистые функции: клик, покупка, тик
    └── ui/
        ├── mod.rs
        ├── app.rs         # корневой компонент и раскладка
        ├── topbar.rs
        ├── sections.rs    # сворачиваемые разделы
        ├── resources.rs
        ├── tabs.rs
        └── energy.rs
```

Принципы:

- **Логика отдельно от UI.** `game/` не знает про Dioxus. Это позволяет тестировать
  `cargo test` без запуска приложения.
- **Состояние — один `GameState`**, доступный через `Signal<GameState>` или
  контекст. UI только читает и вызывает действия.
- **Баланс — в одном файле** `balance.rs`, чтобы крутить числа без правок логики.
- **Сохранение** — позже: `serde` + JSON, хранение в localStorage/WebView.

## 7. Как запускать

### Быстрая итерация (десктоп)

```powershell
cd C:\Users\boba\Documents\medieval-idle
dx serve --platform desktop
```

### Android

1. Запустить эмулятор из Android Studio (Device Manager) или:
   ```powershell
   emulator -avd <имя_AVD>
   ```
2. Проверить, что устройство видно:
   ```powershell
   adb devices
   ```
3. Собрать и установить:
   ```powershell
   dx serve --platform android
   ```

### Проверка кода без запуска

```powershell
cargo check
cargo clippy --message-format=short
cargo test
```
